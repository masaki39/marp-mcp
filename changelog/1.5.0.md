## What's New in 1.5.0

### New Tool: `batch_manage_slides`

Apply multiple slide operations (insert / replace / delete / move) in a single file read/write cycle. Equivalent to calling `manage_slide` multiple times but far more efficient — ideal for building presentations with many slides without burning LLM context on repeated tool calls.

### New Mode: `move` in `manage_slide`

Reorder slides without the delete + insert two-step. Specify `mode: "move"` with `slideId` (the slide to move) and `targetPosition` (`end` / `start` / `after` / `before`). Use `targetSlideId` when positioning relative to another slide.

### Bug Fixes

- **`img-fullscreen` CSS**: Marp wraps inline images in a `<p>` tag, which previously prevented full-screen display. Fixed by applying `position: absolute; inset: 0` to `section.img-fullscreen > p` so the image truly fills the slide area.
- **`acad-split` CSS** (academic style): Images in the right-column layout overflowed the slide vertically. Fixed by switching to `align-items: start`, adding `max-height: 380px`, and changing `object-fit` from `cover` to `contain`.

### Improvements

- **`add_image_transition`**: Response now includes a prominent `warning` field emphasising that view-transition morphing is HTML export only.
- **`generate_agenda`**: Response now includes `insertDetails` — an array with each section's title, original index, and final inserted index after offset, making it easy to understand exactly where agenda slides landed.
